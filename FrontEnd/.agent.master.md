# Master Agent για σύστημα κρατήσεων ιατρειών μικρού νοσοκομείου

## Ρόλος
Είμαι αρχιτέκτονας του συστήματος και συντονίζω το σύνολο της λύσης: frontend, backend, database, security και realtime. Επιδιώκω να σχεδιάζω μια ασφαλή, πλήρως παρακολουθήσιμη και λειτουργικά αποδοτική λύση για μικρό νοσοκομείο με κλινικές, γιατρούς, ambulatory workflows και reservations.

## Κύρια επιχειρηματική απαίτηση
Το σύστημα πρέπει να υποστηρίζει:
- κλινικές και τμήματα,
- γιατρούς και ειδικότητες,
- προγράμματα ωραρίου και διαθεσιμότητας,
- ασθενείς και ιστορικά ραντεβού,
- admin και superuser roles,
- reception και doctor workflows,
- live ειδοποιήσεις με SignalR,
- αυθεντικοποίηση μέσω Gov.gr OAuth/OIDC,
- πλήρη audit trail για κάθε κρίσιμη ενέργεια.

## Preferred stack
- Frontend: React + TypeScript + DevExtreme
- Backend: ASP.NET Core Web API (.net10)
- Database: SQL Server
- Realtime: SignalR
- Auth: Gov.gr OIDC/OAuth 2.0
- Cache/operations: Redis (optional)
- Logging/monitoring: Serilog + OpenTelemetry + Azure App Insights / equivalent

## Απαιτήσεις ρόλων
- Admin
- SuperUser
- ClinicManager / ClinicalAdministrator
- Doctor
- Reception / FrontDesk
- Patient

Κάθε ρόλος πρέπει να έχει ξεκάθαρα δικαιώματα και να ελέγχεται σε API και σε UI.

## Σχεδιαστικές αρχές
- least privilege,
- explicit authorization per endpoint,
- default deny για κρίσιμες λειτουργίες,
- complete audit for create/update/delete and role changes,
- separated admin flows from patient flows,
- data minimization,
- secure defaults,
- business validation before persistence.

## Gov.gr OIDC / OAuth implementation
- χρήση Authorization Code + PKCE,
- validation issuer, audience, signature,
- strict redirect URIs,
- short-lived access tokens,
- refresh token rotation,
- secure storage of tokens,
- mapping external claims to internal roles,
- user provisioning and deprovisioning logic,
- log failed and successful login events,
- MFA for high-risk roles where applicable.

## Security controls
- HTTPS only
- secure cookies if used
- HttpOnly, SameSite, Secure headers
- CORS allowlist
- rate limiting on auth and sensitive endpoints
- brute force protection
- encryption at rest and in transit
- no secrets in repo
- secret manager usage
- readiness for legal/audit review

## Database architecture
- SQL Server schema with normalized entities
- clinic, doctor, department, schedule, appointment, patient, audit logs
- proper indexes on operation-heavy queries
- foreign keys and validation constraints
- no-overlap logic for same doctor schedule
- datetimeoffset for timezone-safe operations
- audit tables separate from operational tables
- soft delete or historical status for critical records

## SignalR design
- groups by clinic, department, doctor, patient, admin
- event-driven notifications for appointment created, cancelled, confirmed, rescheduled
- role-based visibility on live events
- logging all real-time events
- subscription authorization per user and scope

## UI design with React + DevExtreme
- devextreme scheduler for doctor calendars
- devextreme datagrid for appointment lists and admin dashboards
- role-based screens for admin, doctor, reception, patient
- validation forms with clear UX states
- fast lists and filters
- user permissions reflected in visible actions

## Audit requirements
Πρέπει να υπάρχει πλήρης audit για:
- login/logout
- failed login attempts
- role assignments
- clinic creation/update/delete
- doctor creation/update/delete
- schedule changes
- appointment changes
- cancellation and reschedule
- admin actions
- report exports
- security events

Κάθε event να περιλαμβάνει:
- userId
- role
- timestamp
- action type
- entity type
- entityId
- source IP
- user agent
- before/after snapshot where feasible
